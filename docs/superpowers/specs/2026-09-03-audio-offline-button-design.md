# 音频离线时保留按钮操作设计

## 目标

树莓派未检测到麦克风或扬声器时，网页统一按钮仍保持可操作。音频设备状态只用于提示现场人员，不再作为前端禁止操作的条件。

## 交互行为

- 音频设备在线时，现有对话、知识补充和模式切换流程保持不变。
- 音频设备离线时，统一按钮仍可短按和长按。
- 短按开始树莓派录音时，前端照常调用录音接口。
- 后端在真正启动录音前检查麦克风和扬声器，并返回具体错误，例如“未检测到可用麦克风”或“未检测到可用扬声器”。
- 前端显示后端返回的错误，不把错误改写成笼统的服务不可用。
- 录音启动失败后，按钮恢复可操作，当前交互模式保持不变，用户连接设备后可以立即重试。
- 长按模式切换、退出空白知识补充、浏览器是非判断和舵机动作预览不受树莓派音频状态影响。

## 实现边界

- 保留 `/api/device/state` 返回的音频设备状态字段和页面状态提示。
- 删除统一按钮禁用条件中对 `audioAvailability.ready` 的依赖。
- 保留后端 `LocalAudioController.ensure_ready_for_recording()` 和设备探测逻辑，设备错误以现有 API 错误映射返回。
- 不增加浏览器麦克风自动回退，不自动重试，不修改树莓派音频设备配置。
- 不修改 XZKB、ASR、TTS、知识补充保存协议或舵机协议。

## 失败处理

- 麦克风缺失：显示“未检测到可用麦克风”。
- 扬声器缺失：显示“未检测到可用扬声器”。
- 设备探测异常：显示后端提供的音频设备错误。
- 请求结束后清除前端 pending 状态并恢复按钮，避免失败后无法再次操作。

## 验证

- JavaScript 单元测试证明音频离线不会禁用统一按钮。
- 页面/API 集成测试证明音频状态仍正常显示，录音请求仍由后端拒绝并返回具体错误。
- 运行完整 Python、JavaScript 测试和 Python 编译检查。
- 部署后验证健康接口、页面脚本和服务状态。
