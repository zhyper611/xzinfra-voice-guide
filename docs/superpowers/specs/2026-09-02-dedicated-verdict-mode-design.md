# 独立是非判断模式设计

## 文档状态

本设计取代 `2026-09-01-ai-verdict-servo-design.md`。旧设计中“讲解回答与舵机判断同时发生”“通过 XZKB 空回复识别日常问题”和“判断后自动回中央”等定义不再适用。

本设计只定义需求和边界，不代表当前代码已经实现、提交或部署。

## 目标

在现有 Raspberry Pi 5 展厅语音讲解器中增加第三种、由用户主动进入的“是非判断模式”。设备的三种功能互斥：

- 对话模式负责展厅讲解和语音回答。
- 是非判断模式只判断问题并用舵机表达结果，不生成正常语音回答。
- 知识补充模式负责录入、复述确认和保存知识。

是非判断模式同时接受展厅相关和日常低风险的是非问题。AI 思考期间舵机缓慢左右摇摆；结果为“是”或“否”时，舵机先运动到结果反方向，再无停顿地快速转到结果方向并保持；无法判断时执行中立动作。

## 成功标准

- 用户只用一个实体按钮即可操作三种模式。
- 三种模式行为互斥，不再自动从普通对话中触发舵机判断。
- 是非判断模式可连续提问，直到用户主动切换模式。
- 是非判断每轮在 ASR 后只调用一次混合判断应用。
- 对话模式保留现有 FAQ 文本缓存、预制音频、XZKB 和 TTS 流程。
- 是非判断模式不访问 FAQ 讲解缓存，也不生成正常答案 TTS。
- 思考动作在 ASR 成功后 0.2 秒内开始，并在判断结束或超时后停止。
- 舵机左侧表示“是”，右侧表示“否”，中央表示中立。
- 明确结果保持在左侧或右侧，直到下一次结果覆盖或用户离开是非判断模式。
- 判断服务、舵机或 GPIO 失败不能影响对话、知识补充和普通网页多人会话。
- 设备测试页提供同级的“对话 / 是非判断 / 知识补充”切换；网页是非判断调用真实 ASR 和混合判断应用，但默认只运行动画，不访问 GPIO。
- 网页和实体设备共用判断状态机与动作协议，分别使用独立会话和输出适配器，购买硬件后不重写业务流程。

## 非目标

- 不自动识别普通对话中的问题是否适合舵机判断。
- 不在一次提问中同时播放讲解和执行“是/否”动作。
- 不让模型输出 GPIO、PWM、角度、速度或动作时序。
- 不修改 XZKB 源码。
- 不使用连续旋转的 360 度舵机实现位置指示。
- 不要求首版新增第二个实体按钮、显示屏、灯光或复杂连杆。
- 不让普通多人网页对话驱动实体舵机。

## 三模式状态机

设备启动后始终进入对话模式，不恢复重启前的模式。

| 当前模式和状态 | 短按 | 长按 |
| --- | --- | --- |
| 对话模式，空闲 | 开始录音 | 进入是非判断模式 |
| 对话模式，录音中 | 停止录音并开始讲解 | 不执行切换 |
| 是非判断模式，空闲 | 开始录音 | 进入知识补充模式 |
| 是非判断模式，录音中 | 停止录音并开始判断 | 不执行切换 |
| 是非判断模式，处理中 | 不启动新任务 | 不执行切换 |
| 知识补充，等待录音 | 开始录音 | 取消补充并返回对话模式 |
| 知识补充，录音中 | 停止、识别并复述 | 不执行切换 |
| 知识补充，等待确认 | 重新录制 | 保存并返回对话模式 |

成功切换模式时播放本地预制提示音：

- “已进入对话模式”。
- “已进入是非判断模式”。
- “已进入知识补充模式”。

提示音不调用在线 TTS。模式切换只允许在相应空闲或确认状态执行。离开是非判断模式时舵机回中央、关闭 PWM；进入是非判断模式后舵机从中央待机。

舵机保持上一轮 `yes/no` 结果时，设备在交互上仍属于“是非判断模式，空闲”：短按可以开始下一轮录音，长按可以进入知识补充模式。“处理中”只包括 ASR、应用请求、结果校验和结果动作尚未完成的阶段。

## 应用架构

### 现有展厅讲解应用

- 关联展厅知识库。
- 保持“仅关联知识库”开启。
- 系统提示词继续以自然、由浅入深、适合口播的展厅讲解为目标。
- 只供对话模式调用。

### 新建混合是非判断应用

- 关联与讲解应用相同的展厅知识库。
- 关闭“仅关联知识库”。
- 不启用图表分析等与判断无关的工具。
- 只供是非判断模式调用。
- 在一次调用中完成问题范围识别和 `yes`、`no`、`neutral` 裁决。
- 展厅问题优先依据关联知识库；日常问题使用模型通用能力。
- 只返回固定 JSON，不生成面向用户的长回答。

采用混合应用是明确的性能取舍：减少串行模型调用，接受展厅判断无法获得平台级“只使用知识库”强约束。通过提示词、证据字段和树莓派校验降低风险，但不能宣称与开启“仅关联知识库”等价。

## 各模式调用链

### 对话模式

```text
录音 -> ASR -> FAQ 讲解缓存
                    |-- 预制音频命中 -> 直接播放
                    |-- 文本命中 -> TTS -> 播放
                    `-- 未命中 -> 展厅讲解应用 -> TTS -> 播放
```

现有多轮上下文、展项追问、空回复处理和播放失败降级保持在对话模式内。对话模式不调用混合判断应用，不更新判断结果，不触发判断动作。

### 是非判断模式

```text
录音 -> ASR 成功 -> 启动思考摇摆
                    -> 混合是非判断应用（一次调用）
                    -> 校验结构化结果
                    -> 停止思考动作
                    -> 执行 yes / no / neutral 动作
```

是非判断模式不访问 FAQ 缓存，不调用展厅讲解应用，不生成正常回答 TTS。只有中立、输入错误或服务故障时允许播放短提示。

### 知识补充模式

沿用现有录音、ASR、复述、短按重录、长按保存并返回对话模式的流程。知识写入同一个展厅知识库后，讲解应用和混合判断应用都可以检索到新增内容。

## 统一工作流与输出适配器

网页测试和实体按钮不能各自实现一套判断逻辑。两者共用三模式状态机、`VerdictWorkflow` 和以下动作协议：

```text
短按 / 长按 -> 三模式状态机 -> 录音或 WAV -> ASR -> VerdictWorkflow
                                                    -> thinking
                                                    -> windup
                                                    -> decisive
                                                    -> holding / neutral
```

工作流只产生抽象动作事件，不包含 GPIO、PWM 或浏览器 DOM 操作。每个事件至少包含动作类型、`verdict` 和不可复用的轮次编号。

- 网页会话使用 `WebSimulationOutput`：把动作写入当前浏览器会话状态，由前端动画消费；不创建舵机驱动，不访问 GPIO。
- 实体设备使用 `ServoMotionOutput`：把相同动作映射为舵机角度和时序。
- 两种输出实现相同的 `thinking`、`show_verdict`、`show_neutral` 和 `reset` 边界。
- 网页和实体设备拥有独立状态存储与轮次编号，任何一方切换模式、录音或取消都不能改变另一方。

未来购买硬件后只启用 GPIO、配置舵机角度并装配 `ServoMotionOutput`；ASR、混合应用、判断校验、模式状态机和失败处理不改变。

## 结构化判断协议

混合判断应用固定返回：

```json
{
  "scope": "exhibition",
  "verdict": "yes",
  "basis": "knowledge_base",
  "reason": "知识库明确说明该系统支持国产算力适配",
  "evidence": "将不同类型的国产芯片整合并进行适配和优化"
}
```

字段约束：

- `scope` 只能为 `exhibition`、`casual` 或 `invalid`。
- `verdict` 只能为 `yes`、`no` 或 `neutral`。
- `basis` 只能为 `knowledge_base`、`general` 或 `none`。
- `reason` 必须是非空字符串，去除首尾空白后不超过 120 个字符，只供测试页和日志显示。
- `evidence` 去除首尾空白后不超过 200 个字符；日常、无效和无依据的中立结果必须使用空字符串。

树莓派执行以下强制校验：

- `scope=exhibition` 且结果为 `yes/no` 时，`basis` 必须为 `knowledge_base`，`evidence` 必须非空，否则强制改为 `neutral`。
- `scope=casual` 时，`basis` 必须为 `general` 或 `none`。
- `scope=invalid` 时，结果必须为 `neutral`，`basis` 必须为 `none`。
- 未知枚举、缺失字段、非 JSON、超长字段或不一致组合一律降级为 `neutral`。
- 模型输出只解释为预定义枚举和文本数据，绝不解释为硬件命令。

## 判断语义

### 展厅问题

展厅、展项、公司、产品、技术、能力、案例、性能数据和现场指代属于 `exhibition`。只有检索到的知识内容明确支持命题或其反命题时才允许 `yes` 或 `no`。

以下情况必须为 `neutral`：

- 没有相关知识、只有空回复或模型未提供知识依据。
- 依据模糊、相互冲突或只支持部分命题。
- 问题缺少产品、版本、时间、条件或比较标准。
- 问题是开放式讲解请求而非是非命题。

关闭“仅关联知识库”后，`basis` 和 `evidence` 是模型自报信息，不能从技术上证明结论未使用模型常识。测试和验收必须重点覆盖公司专有事实、知识缺失和诱导模型编造的问法。

### 日常问题

普通、低风险、可以合理回答是或否的问题属于 `casual`。模型可以结合用户语气给出友好、有趣且相对明确的选择，不需要语音解释理由。

医疗、法律、投资、借贷、博彩、人身安全、危险操作、人事评价、违法行为或可能造成明显现实损失的问题必须为 `neutral`。不得为了迎合而歪曲明确事实。

### 无效问题

开放式请求、无法理解、关键指代缺失或本身不能合理二元判断的问题属于 `invalid`，返回 `neutral`，并提示：“请换成可以回答是或否的问法。”

## 舵机动作语言

使用可定位角度的 180 度或 270 度位置舵机。360 度连续旋转舵机通常只能控制方向和速度，不能可靠保持左、中、右三个位置，不适用本设计。

模型只产生判断枚举，本地动作控制器负责全部编排。

### 思考

- ASR 成功后立即开始。
- 围绕中央位置缓慢、连续地左右摇摆。
- 单程目标约 0.6 至 0.8 秒，实际角度和速度通过配置及实体调试确定。
- 录音期间不运动，避免机械噪声进入麦克风。
- 判断返回、任务取消或硬超时后立即终止思考循环。

### 明确判断

```text
yes：思考摇摆 -> 到达右侧蓄势位置 -> 无停顿快速移动到左侧 -> 保持左侧
no： 思考摇摆 -> 到达左侧蓄势位置 -> 无停顿快速移动到右侧 -> 保持右侧
```

如果结果到达时舵机正在结果侧，动作控制器仍先移动到反方向，再快速转到结果侧，使每次判断具有一致的机械语义。最终快速移动目标约 0.2 至 0.3 秒，不插入停顿，不自动回中央。

到达结果位置并稳定后关闭 PWM，以降低嗡鸣、发热和耗电。首版机械指示件必须足够轻，使舵机断开 PWM 后仍能依靠齿轮阻力保持可见位置。

### 中立

中立不执行明确的快速甩动。舵机在中央附近完成一次小幅左、右犹豫后停在中央并关闭 PWM。

根据原因播放本地短提示：

- 非是非问题：“请换成可以回答是或否的问法。”
- 展厅依据不足：“现有展厅资料暂时无法支持判断。”
- 高风险问题：“这个问题不适合进行趣味是非判断。”
- 服务异常：“判断服务暂时不可用，请稍后重试。”

## 结果保持与下一轮

- `yes` 或 `no` 的结果位置保持到下一轮结果覆盖或离开是非判断模式。
- 下一次录音期间舵机保持上次位置且不运动。
- 下一次 ASR 成功后直接从当前位置进入思考动作。
- 如果下一次录音过短、无声或 ASR 失败，录音结束后执行中立动作，避免旧结果看起来像是在回答失败的问题。
- 离开是非判断模式、服务关闭或设备重启时回中央并关闭 PWM。

## 状态与并发

设备状态需要区分：

- `interaction_mode`：`conversation`、`verdict`、`knowledge`。
- `verdict_phase`：`idle`、`thinking`、`windup`、`decisive`、`holding`、`neutral`、`failed`。
- `scope`、`verdict`、`basis`、`reason`、`evidence`。
- ASR 文本、各阶段耗时和当前设备错误。

每轮判断生成不可复用的轮次编号。旧请求晚返回、模式切换、取消或新轮开始后，旧结果不得更新状态或驱动舵机。设备同一时间只处理一个本地录音或判断任务。

普通网页多人会话使用独立会话控制器，不驱动实体舵机。设备测试页默认创建网页会话自己的三模式状态机和 `WebSimulationOutput`。即使树莓派已安装并启用实体舵机，网页切换模式、上传 WAV 或使用浏览器录音也不能驱动实体舵机。若未来新增“控制实体设备”，必须作为受设备密钥保护、默认关闭的独立能力重新设计，不属于本期范围。

## 超时与降级

性能目标：

- ASR 成功后 0.2 秒内启动思考动作。
- 日常判断尽量在 4 秒内完成。
- 展厅判断尽量在 10 秒内完成。
- 混合判断整轮硬超时默认 15 秒，可通过配置调优。

故障行为：

- 录音过短：沿用现有无语音错误处理，随后中立。
- 无声、ASR 失败：播放现有提示，随后中立。
- 判断超时、网络失败、鉴权失败或 JSON 无效：中立动作和服务异常提示。
- 舵机失败：熔断机械功能，不传播到对话或知识补充；是非模式播放“机械指示暂时不可用”。
- 模式切换提示、错误提示和中立提示播放失败：记录错误但不改变模式和判断状态。
- 应用未配置：是非判断模式不可用，对话和知识补充继续工作。

## 配置与密钥

混合应用使用独立配置，不复用讲解应用 Key：

```dotenv
GUIDE_VERDICT_ENABLED=false
GUIDE_VERDICT_BASE_URL=http://xzkb.example.invalid
GUIDE_VERDICT_API_KEY=replace-with-verdict-application-key
GUIDE_VERDICT_TIMEOUT_SECONDS=15

GUIDE_SERVO_ENABLED=false
GUIDE_SERVO_PIN=18
GUIDE_SERVO_MIN_ANGLE=10
GUIDE_SERVO_MAX_ANGLE=140
GUIDE_SERVO_YES_ANGLE=20
GUIDE_SERVO_NEUTRAL_ANGLE=75
GUIDE_SERVO_NO_ANGLE=130
```

应用 Key、登录凭据和设备密钥只存在于树莓派 `.env` 或受保护的运行环境中，不进入代码、日志、测试数据或 Git。

## 测试页

设备测试页显示：

- 当前交互模式和判断阶段。
- ASR 识别文本。
- `scope`、`verdict`、`basis`、`reason` 和 `evidence`。
- 舵机当前动作：思考、反向蓄势、快速判断、保持、中立或故障。
- ASR、混合应用和整轮耗时。

设备测试页在现有对话和知识补充切换区域增加“是非判断”，形成同一层级的三个模式入口。切到是非判断后：

- 浏览器录音和 WAV 上传均调用真实 ASR 与混合判断应用。
- 请求开始后立即显示思考动画，结果返回后显示反向蓄势、快速判断和保持结果。
- `yes/no` 不播放正常语音回答；中立与错误继续使用短提示。
- 页面继续提供独立“动作预览”，用于不调用 ASR 和 AI 时检查动画。

测试页默认只使用 `WebSimulationOutput`，不能驱动实体舵机。模拟器或测试页失败不得影响本地按钮流程。

## 当前未提交实现的处理

当前 `feat/servo-motion` worktree 中存在基于旧设计的未提交实现。实施新设计时：

- 不创建用于撤销未发布代码的 revert commit。
- 保留已经验证有价值的 `Verdict` 枚举、严格解析、轮次失效、GPIO 故障隔离和前端模拟测试思路。
- 删除“用 XZKB 空回复识别日常问题”的分流逻辑。
- 删除“讲解 TTS 与后台舵机判断并行”的行为。
- 将判断服务改为只在显式是非判断模式调用。
- 将固定位置动作扩展为思考循环、反向蓄势、快速判断和结果保持。
- 合并时逐文件核对工作区中其他人的改动，不覆盖来源不明的修改。

## 自动测试

- 三模式全部状态下的短按、长按和非法操作。
- 启动默认对话模式，重启不恢复旧模式。
- 对话模式保留 FAQ、预制音频、XZKB、TTS 和多轮上下文，且不调用判断应用。
- 是非模式不访问 FAQ、不调用讲解应用、不生成正常 TTS。
- 混合应用 JSON 的所有合法组合和非法组合。
- 展厅 `yes/no` 缺少知识依据时强制中立。
- 日常低风险明确判断、高风险中立、开放问题中立。
- ASR 后立即启动思考，录音期间不运动。
- `yes/no` 先到反方向，再无停顿快速到结果侧，并保持不回中。
- 中立犹豫动作、失败提示和离开模式回中。
- 旧轮次、超时任务和模式切换后的结果不能更新舵机。
- 舵机、判断应用和提示音故障不影响其他模式。
- 普通网页多人会话不能驱动实体舵机。
- 网页与实体设备共用状态机和动作协议，但状态、轮次和输出适配器相互隔离。
- 网页是非模式实际调用 ASR 和混合判断应用，默认不创建 GPIO 驱动。

## 树莓派验收

1. 舵机功能关闭时，对话、网页和知识补充行为与当前正式版本一致。
2. 单按钮按设计完成三模式切换，每次提示准确且无明显等待。
3. 录音期间舵机无动作，ASR 后立即缓慢左右摇摆。
4. 连续测试至少 10 个展厅是非问题、10 个日常问题、10 个非是非或证据不足问题。
5. “是”和“否”都呈现先到反方向再快速判断的动作，无停顿且结果不自动回中。
6. 下一轮录音失败后旧结果被中立动作清除。
7. 断开判断服务、配置错误 Key、返回非法 JSON、断开舵机时，其他模式仍可使用。
8. 从装置正面校准左“是”、右“否”，连续执行 100 次后舵机不过热、无持续 PWM 嗡鸣。
